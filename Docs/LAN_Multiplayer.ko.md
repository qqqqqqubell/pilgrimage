# Pilgrimage LAN 멀티플레이

기준: Unity 6000.6.9f1, 2026-11-15 Final의 45종 카드. 기존 싱글플레이의 `GameSession`, 효과 핸들러, AI, 지속 효과, 무작위 보상, 승리 계산을 공통으로 사용한다. Scene을 교체하거나 수동 UI 제작을 요구하지 않는다. Git Commit/Push는 수행하지 않는다.

## 실행

1. Unity에서 패키지 해석과 컴파일이 완료될 때까지 기다린다.
2. `Assets/Scenes/PilgrimageDemo.unity`를 열거나 `Pilgrimage > v2 데모 열기` 메뉴를 사용하고 Play를 누른다.
3. **싱글플레이**: 기존 교단 선택 → 인간 1명 + AI 3명. 네트워크 객체나 소켓을 생성하지 않는다. Editor/Development Build의 카드 실험실을 유지한다.
4. **LAN 멀티플레이**: 이름·방 이름·포트(기본 UDP 7777)를 입력하고 **방 만들기**를 누른다. 로비에 호스트의 LAN IPv4와 포트가 표시된다.
5. 다른 실행 인스턴스에서는 **LAN 멀티플레이** → 호스트 IPv4와 같은 포트 → **참가하기**. 같은 PC에서는 Editor와 Windows 빌드 또는 빌드 두 개를 실행하고 `127.0.0.1`로 접속한다. 호스트 두 개를 띄우면 포트를 다르게 해야 한다.
6. 참가자 전원이 희망 교단을 고르고 **준비**를 누른다. 호스트가 **게임 시작 · 배정**을 누르면 최종 4개 교단과 배정 시드를 모두에게 표시한다. 모든 인간이 **배정 확인**을 누른 뒤에만 게임과 라운드가 생성된다.
7. 인간 2~4명, 나머지는 AI. 자기 손패는 항상 하단이다. 상대는 자기 좌석 기준으로 상단·좌측·우측에 배치된다. 클릭/방향키 선택, 우클릭/Space 상세, 더블클릭/Enter 사용, 대상 버튼, 카드 대상 선택, 행동 종료를 유지한다.
8. 라운드 보상은 호스트에서 각 교단에 무작위로 이미 지급한 결과다. 획득 카드와 실제 도착 더미를 표시하고, 연결된 인간 전원이 확인하면 계속한다.
9. **LAN 나가기**로 나간다. 클라이언트가 게임 중 나가면 해당 좌석은 AI가 인계한다. 호스트가 나가면 방이 닫히고 클라이언트는 안내와 함께 모드 메뉴로 돌아간다.

Windows 빌드는 File > Build Profiles에서 Windows 프로필에 기존 `PilgrimageDemo` Scene을 포함하여 만들 수 있다. 실험실이 필요한 싱글플레이 빌드는 Development Build를 사용한다. LAN 차단은 Development Build와 Editor에서도 동일하다.

## 패키지와 통신

- 공식 Netcode for GameObjects **2.14.0**.
- Unity 6000.6.9f1 내장 Unity Transport **6.6.0**. NGO의 최소 의존성은 Transport 2.6.0이지만 이 에디터의 실제 Package Manager는 내장 6.6.0을 선택한다. manifest와 lock에도 실제 버전을 명시했다.
- NGO 2.7.0은 이 에디터의 `EntityId` API에서 컴파일되지 않아 채택하지 않았다. 패키지 소스를 임의 수정하지 않았다.
- Relay, Lobby Service, Unity 계정, 전용 서버, 외부 인터넷 서비스는 사용하지 않는다. LAN 호스트는 `0.0.0.0`에 UDP 수신한다. 클라이언트는 IPv4 직접 접속한다.
- NetworkObject/NetworkBehaviour, Scene 동기화, 전체 게임 직렬화를 사용하지 않는다. NGO Custom Messaging의 신뢰성 있는 분할 순차 메시지로 명령과 수신자별 화면 DTO를 주고받는다.
- 첫 패키지 설치에는 Unity 레지스트리 접근이 필요하다. 설치 후 싱글플레이와 LAN 실행은 오프라인으로 가능하다.

공식 근거: [NGO 패키지 문서](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.14/manual/index.html), [Connection approval](https://mp-docs.dl.it.unity3d.com/netcode/current/basics/connection-approval/), [Custom messages](https://mp-docs.dl.it.unity3d.com/netcode/current/advanced-topics/message-system/custom-messages/). 최종 호환 판정은 설치된 에디터에서의 실제 컴파일과 통신 테스트를 기준으로 한다.

## 권한 및 비공개 정보

`LanRoom`은 실제 접속 ID를 좌석에 매핑한다. 요청에는 조작할 플레이어 인덱스, 자원, 덱, 효과 결과를 넣을 수 없다. 카드 GUID·대상 의도·행동 종료만 전달한다. 세션 ID, 접속 소유권, 단조 증가 요청 번호, 상태 버전, 라운드, 현재 턴, 애니메이션 처리 잠금, 실제 `GameSession.CanPlay`를 검증한다. 공개한 뒤 호스트의 `TryPlay`를 한 번만 호출하며, 실패 시 비용을 지불하지 않는다. 이미 사용한 GUID와 재전송 요청은 다시 사용할 수 없다.

호스트만 실제 GameSession을 소유한다. 클라이언트에는 GameSession을 생성하거나 복원하지 않는다. `LanGameView`에는 다음만 존재한다.

- 자신의 손패 정의 ID/GUID와 현재 비용, 필요한 고유 카운터
- 카드 효과가 허용하는 자기 카드 선택 후보(자기 더미 정보, GUID 순으로 정렬하여 덱 순서 제거)
- 각 교단의 공개 자원·신도 수·더미 장수·공개 지속 효과
- 사용이 공개된 카드, 효과 결과, 공개된 무작위 보상, 승리 결과

상대 손패 카드 목록·상대 덱 구성/순서·비공개 대상 GUID·셔플 RNG 시드는 보내지 않는다. 교단 배정 시드와 게임 난수 시드는 분리한다. 배정 시드는 로비에 공개하고, 실제 게임 시드는 호스트 개발 로그에만 기록한다. 카드 카탈로그 자체는 공개 규칙이므로 모든 클라이언트에 있다.

카드 공개는 실제 카드 더미를 복제하지 않는 표시 참조다. 호스트가 공개 → 이동 시간 대기 → 효과 한 번 처리 → 나머지 표시 간격 대기 → 잠금 해제 순서를 관리한다. 모든 인스턴스는 같은 공개 이벤트를 자기 화면의 상대 위치에서 중앙으로 이동시킨다. 공개 시간과 이동 시간은 기존 DemoSettings AI 설정을 재사용한다.

AI는 호스트의 기존 RuleBasedAi/AiTurn만 실행한다. 클라이언트 UI에서 기존 싱글 AI 코루틴은 실행하지 않는다. LAN은 호스트가 빈자리/퇴장 좌석 AI를 항상 진행하며, 싱글플레이의 AI 수동 테스트 설정과 분리된다.

LAN의 실험실 버튼을 숨기고 UI 진입도 차단한다. 서버 명령은 허용 목록만 처리하며 Debug 명령은 호스트도 거부한다. 네트워크 GameSession에 대한 `GameDebugTools` 카드 지급·손패 구성·자원 변경 API도 예외로 거부한다.

## 교단 중복 배정

1. 희망자가 정확히 한 명인 교단을 먼저 그 사람에게 배정한다.
2. 남은 교단 목록을 호스트의 배정 시드로 Fisher–Yates 셔플한다.
3. 충돌한 인간을 접속 순서대로 남은 교단에 배정하고, 나머지는 AI 좌석에 배정한다.
4. 이 배열을 한 번만 생성해 모든 참가자에게 보내고 확인을 받는다. 실제 게임의 플레이어 순서도 이 배열과 같다. 로비 확인 중 누군가 나가면 로비로 돌아가 준비/배정을 다시 한다.

싱글플레이는 인간 인덱스 0을 유지한다. LAN에서는 인간들이 접속 순서의 0~N-1 좌석을 가지며 각 화면은 LocalSeat를 기준으로 표시한다. 보상 확인은 네트워크 권한 계층에서 인간들의 확인을 모은 뒤 기존 엔진의 공통 라운드 전환 API를 한 번 호출한다.

## 연결과 제한

- 게임 시작/교단 배정 이후 신규 접속은 거부한다.
- 로비 퇴장 시 명단에서 제거한다. 게임 중 퇴장 시 좌석·카드·교단을 유지한 채 AI로 인계한다.
- 접속 시 약 12초 제한, Transport 연결 시도/연결 끊김 제한, 버전/카탈로그 불일치 오류, 만원/이미 시작 오류를 표시한다.
- 호스트 이전과 중도 재접속, 저장/불러오기, 관전, NAT traversal, 암호/암호화는 지원하지 않는다. 같은 신뢰할 수 있는 LAN을 대상으로 한다.
- 클라이언트가 연결을 유지한 채 행동/보상 확인을 하지 않으면 기다린다. 강제 턴 타이머는 기획에 없으므로 추가하지 않았다.
- 최신 Final 문서의 미확정 카드 처리 정책은 기존 `TimedEffectPolicy`/`DemoRuleAssumptions`를 유지하고 호스트만 적용한다. 멀티플레이용 카드 효과나 경제 규칙을 별도로 만들지 않는다.

## Windows 방화벽과 다른 PC

호스트 PC의 방화벽에서 Unity Editor 또는 해당 Windows 실행 파일의 **개인 네트워크** 접근을 허용한다. 필요하면 선택한 UDP 포트(기본 7777)에 대한 인바운드 허용 규칙을 사용한다. 이 작업은 방화벽을 자동 변경하지 않는다. 게스트 Wi-Fi의 AP 격리, 서로 다른 VLAN, VPN 가상 어댑터 주소, 공용 네트워크 프로필은 접속을 막을 수 있다. 클라이언트는 `0.0.0.0`이나 다른 PC에서의 `127.0.0.1`이 아니라 호스트의 실제 LAN IPv4를 입력해야 한다. 라우터 포트 포워딩은 같은 LAN에서 필요하지 않다.

## 검증 및 파일

검증 결과와 변경 파일별 역할은 `LAN_TestReport.ko.md`에 기록한다. 자동 실행 도구:

```powershell
./Tools/verify_unity.ps1 -Platform EditMode -BuildLanPlayer
./Tools/verify_unity.ps1 -Platform PlayMode
./Tools/verify_lan.ps1 -PlayerPath '<위 출력 LAN_PLAYER 경로>'
```

검증은 원본 Library/Temp/Logs 대신 OS 임시 프로젝트와 임시 빌드에서 수행한다. 테스트 프로세스는 숨겨진 창으로 실행한다. 서로 다른 물리 PC의 LAN 검증은 위 loopback 자동 테스트와 별도로 수행해야 한다.

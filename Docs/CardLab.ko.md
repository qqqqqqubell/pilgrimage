# 카드 실험 모드와 포고령 구현

기준 기획서: `Docs/Pilgrimage_Game_Design_2026-11-14.md`. 기존 Scene과 정규 게임의 초기 덱/드로우/보상 규칙은 유지합니다. Commit과 Push는 수행하지 않습니다.

교단 선택과 지속 효과 7종 구현이 추가되었습니다. 최신 정책·검증 결과는 [지속 효과 및 교단 선택](TimedEffectsAndFactions.ko.md)을 확인하세요. 아래 기존 검증 결과는 이전 구현 단계의 기록입니다.

![실제 Unity 카드 실험 화면](Images/CardLab.png)

## 확인한 원인과 카드 동기화

- 현재 카탈로그에는 일반 22종·교단 16종, 총 38종이 등록되어 있습니다. 신앙의 결속 삭제 검사도 남아 있지 않습니다.
- 정규 초기 덱은 신도 5 / 포교 4 / 헌금 요구 3 / 정기 예배 3입니다. 포고령·설파·신앙의 결속·공격적 선교는 초기 덱에 없으므로 초기 드로우에서 나오지 않는 것이 현재 규칙에 맞습니다. 정규 게임에서는 보상 등으로 획득해야 합니다.
- 기존 포교·설파·신앙의 결속·공격적 선교 효과를 재사용했습니다. 실제 누락 기능은 포고령의 제거 대상 선택과 효과였습니다. 이제 대상 검증·제거 처리·선택 UI를 구현했습니다.
- 생성 스크립트에서도 포고령을 미구현 목록에서 제거하고 카드 대상 메타데이터를 추가했습니다. `py Tools/import_card_design.py --check`로 최신 문서/생성 스크립트/생성 파일의 완전 일치를 검사합니다. 재생성 시 수동 수정이 사라지는 방식이 아닙니다.
- 헌금 요구 0, 성직자 양성 2, 고해성사 5, 공격적 선교 X(신앙심 30 이하 1/그 외 2), 대주교 이름 등 최신 데이터와 기존 테스트를 유지합니다.

## Unity에서 바로 테스트하기

1. Play를 중지하고 스크립트 컴파일을 기다립니다.
2. Unity 메뉴 **Pilgrimage → v2 데모 열기 → Play → Game**으로 실행하고, 네 교단 중 하나를 선택합니다. 선택 전에는 게임/AI가 시작되지 않습니다.
3. **Game 화면 상단의 카드 실험** 버튼을 누릅니다. 기존 카드 도감 안의 카드 실험 버튼도 같은 실험 모드로 연결됩니다.
4. **필드로 닫기**를 누르면 기존 부채꼴 손패에 포교·포고령·설파·신앙의 결속·공격적 선교가 각 1장 보입니다.
5. 카드의 더블클릭/Enter로 사용합니다. 우클릭/Space 상세보기, Hover, 방향키도 기존대로 동작합니다.
6. 포고령은 사용 시 별도의 목록에서 **자기 손패 또는 덱의 제거 대상 1장**을 선택합니다. 취소/ESC는 비용을 소모하지 않습니다.
7. 다른 교단 대상은 필드의 **대상** 버튼으로 선택합니다.
8. 다시 카드 실험을 열어 **더미 / GUID 확인**으로 상태와 이동 결과를 봅니다.
9. **정규 게임 복귀**를 누르면 보관한 정규 게임 객체로 돌아옵니다. 정규 게임의 자원·카드·라운드는 실험 때문에 바뀌지 않습니다.

실험 도구는 **Unity Editor 및 Development Build**에서만 표시/진입할 수 있습니다. 일반 Release Build에는 실험 진입 버튼이 없고 메서드 진입도 막습니다. 포고령의 정상 카드 선택 UI는 일반 게임에서도 제공됩니다.

## 실험 모드 도구

| 기능 | 조작 |
|---|---|
| 38종 라이브러리 검색 | 이름 검색란에 입력. 구현 상태, 코스트, 손패 존재/현재 사용 가능 여부를 표시 |
| 원하는 카드 추가 | 해당 행의 손패 +1 |
| 특정 5장 구성 | 원하는 행의 5장 선택을 5회 누르고 선택한 5장으로 구성. 같은 카드 중복 선택 가능. 5장 이후 새 선택은 새 목록을 시작 |
| 다섯 행동 카드 프리셋 | 요청한 행동 카드 5장 |
| 행동 불가능 손패 검증 | 신도 5장. 신도는 계속 사용 불가이며 정규 규칙을 완화하지 않음 |
| 빈 손패 | 내 손패 비우기 |
| 상대/자기 자원 변경 | 편집할 교단 변경 → 헌금/신앙심/교리 입력 → 자원 적용. 신앙심/교리는 0~100, 헌금은 최소 0으로 처리 |
| 효과 대상 확보 | 편집 교단을 고른 뒤 이 교단 덱에 신도 추가 |
| 다음 드로우 확인 | 다음 내 차례로. AI 없이 남은 순서를 종료하고 필요한 보상은 첫 항목을 선택하는 명시적 실험 진행 도구 |
| 실제 상태 확인 | 더미 / GUID 확인. 덱의 위→아래 순서·손패·버린 더미·제거 카드와 GUID 앞 8자 표시 |

실험 세션은 생성 시 각 교단 헌금 20/신앙심 50/교리 50, 공용 무신론자 100으로 시작합니다. 각 교단 덱에 신도를 2장씩 실험 대상으로 추가합니다. **이 수치와 대상 추가는 테스트 픽스처이며 정규 초기 설정이 아닙니다.** AI 자동 진행은 실험 세션에서 정지하고 정규 게임에 복귀하면 원래 설정대로 재개합니다.

손패 교체 시 기존 손패는 버린 더미로 옮기고, 선택한 실험 카드만 새 GUID로 생성합니다. 기존 실물 카드를 조용히 삭제하거나 복제하지 않습니다. 실험에서 모든 교단의 더미를 보는 기능은 정규 UI나 AI 관측으로 전달하지 않습니다.

## 다섯 카드의 예상 결과

청빈의 사도단을 선택하고 프리셋에서 순서대로 사용하며 기본 대상(순금의 형제단)을 유지하면 다음을 확인할 수 있습니다. 다른 인간 교단을 선택하면 대상의 교단 이름은 달라지지만 기본 신앙심은 동일합니다.

| 카드 | 비용과 실제 효과 |
|---|---|
| 포교 | 헌금 -1, 공용 무신론자 100→98, 신앙심 50→48, 자기 덱에 새 신도 2장 |
| 포고령 | 헌금 -2, 선택한 자기 손패/덱 카드 1장을 Removed로 이동. 실물 GUID 유지 |
| 설파 | 헌금 -2, 교리 50→60, 자기 덱에 새 포교 1장 |
| 신앙의 결속 | 헌금 -2, 자기 덱의 신도 1장을 대상 덱 **맨 아래**로 이동. 신앙심 48→58, 교리 60→70. 이동한 신도 GUID 유지 |
| 공격적 선교 | 대상 덱 신도 1장을 내 덱으로 강탈. 대상 신앙 50이면 비용 2, 30 이하로 바꾸면 비용 1. 강탈한 실물 GUID 유지 |

포고령으로 자기 덱의 포교 등 신도가 아닌 카드를 제거하고, 대상 신앙을 기본 50으로 두면 다섯 장 사용 후 헌금은 20→11입니다. 대상 신앙을 30으로 바꾸면 20→12입니다. 포고령으로 다른 행동 카드나 신도를 제거하면 이후 효과/사용 가능 여부는 선택에 따라 달라집니다.

포고령은 현재 사용하는 자기 자신, 다른 교단의 카드, 이미 버리거나 제거된 카드, 신실한 신도를 대상으로 받을 수 없습니다. 선택을 확정한 순간에도 엔진이 비용·영역·소유·보호를 재검증합니다. 효과 대상이 지정되지 않았거나 부적합하면 비용/상태를 바꾸지 않습니다. 덱에서 특정하지 않은 신도 선택은 기존처럼 위쪽의 조작 가능한 신도부터 처리합니다.

## AI와 카드 구현 상태

- 기존 구현 카드 선택/비용 검증 흐름을 유지하며 포고령도 평가할 수 있습니다. 자기 손패와 자기 덱의 순서 없는 후보 목록에서 이단/실행할 수 없는 카드를 제거할 가치와 비용을 비교합니다.
- `AiWeights.removeDeadCard`로 제거 가치를 조절합니다. 자기 카드 후보는 GUID 순으로 정렬되어 덱 순서를 평가기로 제공하지 않습니다. 상대 손패/덱 목록은 제공하지 않습니다.
- **38종 모두 효과/상시 특성 연결, 사용 가능한 행동 카드 36종**입니다. 신도·신실한 신도는 사용 불가입니다.
- 고행, 고독한 성찰, 대상단 투자, 마녀사냥, 누추한 성전, 성전 리모델링, 대주교도 실험실에서 사용할 수 있습니다. 각 카드의 기간/중첩/대상 임시 정책은 최신 보고서를 확인하세요.

## 검증과 파일

기존 테스트에 더해 다섯 카드의 정확한 수치·덱 이동·GUID, 공격적 선교의 30/31 경계 및 비용 부족, 포고령의 손패/덱 대상과 보호·취소·중복 클릭, 실험 세션의 정규 게임 보존, 신도 5장, AI의 포고령 사용을 검증합니다.

변경 파일:

- `Tools/import_card_design.py`, `Cards/CardCatalogData.cs`: 38종 동기화, 포고령 구현/카드 대상, 재생성 일치 검사.
- `Game/GameSession.cs`, `SessionCardEffects.cs`: 자기 카드 대상으로 포고령 검증/제거.
- `Game/GameDebugTools.cs`: 명시적 별도 실험 세션과 손패 프리셋/교체.
- `AI/AiStrategy.cs`: 자기 카드 제거 후보와 포고령 평가.
- `UI/V2/DemoController.cs`, 신규 `CardLabUI.cs` 및 `.meta`: 기존 컨트롤러를 partial로 확장. 라이브러리, 자원 편집, 더미 검사, 세션 보존/복귀, 정규 포고령 선택 UI.
- `Tests/EditMode/AiStrategyTests.cs`, `Tests/PlayMode/DemoInteractionTests.cs`: 신규 검증.
- `Tools/verify_unity.ps1`: 렌더링 검증 시 실험 화면도 캡처.
- 이 문서와 이전 안내서의 후속 변경 링크.

검증 결과:

- 최신 기획서와 생성 파일의 일치 검사 통과(`--check`).
- 로직 테스트 48개 통과. 기존 카드/AI/40라운드 테스트를 포함합니다.
- 최종 Unity PlayMode **12개 통과**: 다섯 카드 실제 UI 사용, 포고령 선택/취소/중복 입력, 검색, 자원 편집 입력으로 상대 신앙 30 설정 및 공격적 선교 비용 1 갱신, 신도 손패와 정규 세션 복귀를 포함합니다. 추가 렌더링 시 실행 부하로 기존 AI 복귀 테스트의 10초 대기를 초과한 사례가 있어, 유한 대기 상한을 30초로 조정한 뒤 전체 검증을 다시 통과했습니다. 게임 규칙이나 AI 행동 상한은 바꾸지 않았습니다.
- 실제 1920×1080 실험 화면의 검색 목록·입력란·버튼·한글 배치를 확인했습니다.

Scene/Packages/ProjectSettings는 수정하지 않았습니다. 검사 명령은 `py Tools/import_card_design.py --check`, `Tools/verify_v2.ps1`, `Tools/verify_unity.ps1 -Render`입니다. 검증용 컴파일 결과와 Unity 프로젝트는 OS 임시 폴더에만 생성합니다.

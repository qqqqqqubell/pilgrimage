## 실행

1. Unity **6000.6.9f1**에서 컴파일이 끝날 때까지 기다립니다.
2. 상단 **Pilgrimage → v2 데모 열기**, 또는 `Assets/Scenes/PilgrimageDemo.unity`를 엽니다.
3. **Play → Game**에서 플레이합니다. 내 카드를 사용한 뒤 중앙의 **행동 종료**를 누르면 상대 세 교단이 자동으로 플레이합니다. 선플레이어가 바뀌므로 다음 라운드에도 상대가 먼저 행동할 수 있습니다.

Canvas/TMP/EventSystem을 직접 만들 필요가 없습니다. 기존 Scene 파일과 빌드 목록은 변경하지 않았습니다. 실제 온라인 연결은 없습니다.

마우스 Hover, 우클릭 상세보기, 더블클릭 사용, 방향키 선택, Space 상세보기, Enter 사용, ESC 닫기를 유지했습니다. 기본 화면에는 상대의 교단 이름·신도·헌금·손패 수, 내 주요 수치, 라운드·무신론자·현재 교단·사용 카드·최근 효과만 표시합니다. 아이콘 `人`은 신도, `$`는 헌금, `패`는 손패, `믿`은 신앙심, `율`은 교리 정합성입니다. 자세한 상태는 각 패널의 **상태**, 조작법·최근 기록·초기화·수동 진행은 **메뉴**에서 확인합니다.

**카드 도감**에서 전체 38종의 원문 설명·코스트·Flavor Text·구현 상태를 확인할 수 있습니다. 도감의 **카드 실험**은 전체 카드를 내 손패에 추가하고 테스트 자원을 지급하는 기존 디버그 기능입니다. 정규 획득 규칙이 아닙니다.

## AI 동작

- 자신의 손패, 헌금, 신앙심, 교리 정합성, 신도 수와 교회 재산을 기준으로 판단합니다. 자신의 덱은 순서가 아닌 신도/신실한 신도/이단의 집계만 사용합니다.
- 신도 등 사용 불가 카드, 미구현 카드, 코스트 부족 카드, 공개 정보로 판단 가능한 조건을 만족하지 않는 카드는 후보에서 제외합니다.
- 신자 확보, 수치 유지, 헌금 확보, 상대 견제, 교단 능력, 향후 카드 확보와 비용을 설정된 가중치로 평가합니다. 이미 최대치인 수치를 올리기 위해 자원을 낭비하지 않으며, 낮은 신앙심·교리의 변화에는 설정된 추가 중요도를 적용합니다.
- 높은 점수와 가까운 후보들 사이에서만 무작위로 선택합니다. 청빈·순금·교율·털가죽 교단의 가중치를 각각 설정할 수 있습니다.
- 카드를 한 장 사용한 후 **현재 상태로 새 관측을 만들고 재평가**합니다. 여러 장을 사용할 수 있고, 유리한 후보가 없거나 안전 상한에 도달하면 행동을 종료합니다.
- 상대의 비공개 손패 이름/효과/ID, 덱 순서/구성은 평가기에 제공하지 않습니다. 상대의 공개 수치와 손패 개수만 제공합니다. `RuleBasedAi.Choose`는 `GameSession`을 받지 않고 제한된 `AiObservation`만 받습니다.
- 실제 사용은 사람과 같은 `GameSession.CanPlay`/`TryPlay`를 호출합니다. 상대 덱의 숨겨진 카드 부족 등은 엔진에서 검증하되, 실패한 카드로 상대를 반복 탐색하지 않고 해당 행동 동안 그 실물 카드를 건너뜁니다. 실패 정보의 세부 내용은 평가기로 되돌리지 않습니다.
- AI 보상 선택도 자동 처리하며, 사람의 보상은 사람이 선택합니다. 일반 보상 20종은 스크롤 가능한 화면으로 표시합니다.

AI가 제출한 카드만 이름과 번호, 임시 이미지 영역으로 중앙에 공개합니다. 상대 손패 위치에서 중앙으로 이동한 뒤 비용/효과를 한 번 적용하고, 다음 카드를 공개하기 전에 잠시 유지합니다. 아직 제출하지 않은 카드는 뒷면/개수만 표시합니다. AI 진행 중 플레이·턴 전환·초기화·상세보기 등 상태를 바꿀 수 있는 사용자 입력을 차단합니다.

## 설정 방법

1. Play를 중지합니다.
2. Project 창 우클릭 → **Create → Pilgrimage → v2 데모 설정**으로 `DemoSettings` 에셋을 만듭니다.
3. Demo Scene의 루트 `Pilgrimage Demo v2`를 선택하고 Inspector의 **Settings**에 연결합니다.
4. 설정 에셋에서 **AI**를 펼쳐 값을 조절합니다. 새 게임/Play 재시작으로 적용하세요. 설정을 연결하지 않아도 기본값으로 동작합니다.

| AI 설정 | 기본값/의미 |
|---|---|
| Auto Play | 켜짐. 끄면 메뉴의 AI 수동 진행으로 현재 상대 교단을 진행할 수 있음 |
| Action Safety Limit | 40. AI의 검증 시도와 제출 수에 대한 안전 상한. 실제 게임의 라운드당 카드 사용 제한이 아님. 실행 시 1~200으로 제한 |
| Minimum Score | 0.05. 이 점수 이하이면 사용하지 않음 |
| Similar Score Window | 1. 최고 점수와 이 범위 안에 있는 후보만 무작위 선택 |
| Low Stat Threshold / Multiplier | 35 / 2. 낮은 신앙심·교리의 중요도 보정 |
| Random Seed | -1. 게임별로 다른 난수 사용. 0 이상은 같은 설정/순서의 검증 재현용 |
| Reveal Interval | 1초. 이동+효과 유지의 카드 간격. 임시 연출값이며 기본 권장 범위는 0.8~1.2초. 실행 시 0.1~10초로 제한 |
| Travel Duration | 0.25초. 이동 시간. 실행 시 0.05~2초로 제한. 유지 시간이 최소 0.05초이므로 이 값이 간격보다 크면 전체 간격도 길어짐 |
| Default Weights | Followers/Faith/Doctrine/Offering/Disruption/Faction Ability/Future Cards/Cost |
| Factions | 교단별 가중치. 일치하는 항목이 없으면 Default Weights 사용 |

가중치는 밸런스 확정값이 아니라 규칙 기반 AI 실험값입니다. 신도 수 자체를 자동으로 승리 점수로 확정하지 않았습니다. 소유 교단 카드 외 카드의 사용 자격 등 기획에 없는 규칙도 추가하지 않았습니다.

## 최신 카드와 라운드 규칙

- **일반 22 + 교단 16 = 38종**. 효과 문구·Flavor Text는 새 Markdown 원문에서 가져옵니다.
- 헌금 요구 코스트 **0**, 성직자 양성 **2**, 고해성사 **5**.
- **대주교** 명칭 사용. 기존 실물/설정 데이터의 숫자 ID 위치를 유지하고, 새 12종 ID는 끝에 추가했습니다.
- 신앙의 결속을 포함합니다. 이전 기획의 삭제 카드 검사를 제거했습니다.
- 기존 신실한 신도 보호, 성전 리모델링의 교회 재산 **-4**, 이자의 횟수 제한 없음은 유지했습니다. 신도·신실한 신도는 코스트 없음(None)이며 0코스트로 취급하지 않습니다.
- 새 카드 중 **설파·신앙의 결속·한 줌의 희망·거짓 계시·축복·그곳이 터져 죽습니다·낙원**의 즉시 효과/조건을 연결했습니다. 축복은 자신의 신실한 신도도 패로 옮길 수 있으며 변환·제거·강탈 보호를 손상시키지 않습니다.
- 40라운드, 매 라운드 헌금 5/드로우 5, 선플레이어 순환, 기존 보상 일정은 유지합니다.
- 새 원문에 따라 **교단의 개별 행동 종료가 아닌 라운드 종료에 모든 플레이어의 남은 손패를 버립니다.** 다음 라운드 시작 시 5장씩 뽑으며, 부족하면 버린 더미를 섞어 계속 뽑습니다. 4라운드마다 보상이 있는 경우 손패 정리 → 보상 → 다음 라운드 지급/드로우 순서입니다. 보상 획득 위치는 기존 임시 설정을 유지합니다.

## 사용 중 영역과 카드 이동 — 임시 처리 정책

중앙 테이블은 독립적인 카드 소유 더미가 아닌 **제출/최근 사용 기록의 표시 영역**입니다. `RevealedCardInstanceId`는 모델의 실물 GUID를 참조하고, 중앙 이미지를 만들기 위해 `CardInstance`를 생성하지 않습니다. 기존 효과·더미 동작을 유지하기 위한 임시 선택이며, 향후 반응/취소/동시 제출이 필요하면 별도 InPlay 영역을 설계해야 합니다.

| 단계 | 실물 카드의 모델 위치 | 화면 표시와 중복 방지 |
|---|---|---|
| AI 제출 이동 중 | 손패 | 카드 GUID/정의만 공개 참조. 아직 비용/효과를 적용하지 않음. 손패 개수는 이 카드를 포함 |
| 효과 적용 성공 | 손패 → 버린 더미 | 같은 객체를 한 번 이동. 비용/효과도 한 번 적용. 동일 GUID를 재요청해도 손패에 없으면 거부 |
| 사람의 사용 애니메이션 | 버린 더미 | 기존 즉시 효과 적용 후 사라지는 연출 유지. 남아 있는 CardView도 같은 실물을 표시할 뿐 별도 소유 카드가 아님 |
| 사용 후 중앙에 남은 이미지 | 버린 더미 또는 이후 정상 이동한 위치 | 최근 사용 기록만 표시. 카드 수/신도 수/드로우 풀에 추가하지 않음 |
| 라운드 종료 | 잔여 손패 → 버린 더미 | 이미 사용한 카드는 다시 추가하지 않음. 덱 전체나 제거 영역을 버리는 뜻으로 처리하지 않음 |
| 다음 라운드 드로우 | 덱 → 손패 | 최대 5장. 도중 덱이 비면 버린 더미를 섞어 덱으로 이동하고 부족분만 계속 뽑음 |

라운드 4·12·20·28·36의 일반 보상과 8·16·24·32·40의 교단 보상은 손패 정리 이후 지급합니다. 40라운드 보상을 마치면 41라운드나 추가 드로우 없이 종료합니다. 보상 위치는 임시 설정입니다. 모든 사용 가능 더미가 비면 가상의 카드를 생성하지 않고 드로우를 중단합니다.

생성 효과/보상으로 획득한 새 카드는 새 GUID를 받고, 이동·강탈·변환은 기존 GUID를 유지합니다. 제거된 카드는 Removed 영역에 남겨 추적하지만 신도/보유 수와 재섞기에서는 제외합니다. 따라서 카드 생성이 있는 게임에서 총 카드 수가 늘어나는 것은 정상이며, 중복 판정은 수량 고정이 아닌 **한 GUID가 정확히 한 모델 위치에 존재하는지**로 검증합니다.

계속 분리된 임시 설정/해석: 초기 헌금·교회 재산, 헌금 이월, 행동 종료까지 여러 장 즉시 사용, 보상 획득 위치, 무신론자/효과 대상 신도 부족 시 전체 사용 거부, 특정하지 않은 덱 위치(기본 끝), 깊은 숲의 성역의 4장 단위 계산, 이단의 ‘턴 종료’를 소유 교단 행동 종료로 해석하는 부분입니다. 최종 ‘신자 수’와 ‘가장 많은 카드’가 혼재하므로 승자/동점 판정은 보류합니다.

후속으로 전달된 5~7번 요구사항에 맞춰 라운드/드로우 처리를 재검토하고 카드 보존 검증과 완료 보고를 보완했습니다. Git Commit과 Push는 수행하지 않았습니다.

## 검증

- `Tools/verify_v2.ps1`: 최신 비용으로 갱신한 기존 테스트와 AI 테스트를 합쳐 **로직 테스트 40개 통과**, 런타임/UI/에디터/EditMode·PlayMode 어셈블리 컴파일 성공.
- `Tools/verify_unity.ps1 -Render`: 격리된 Unity 6000.6.9f1 프로젝트에서 **PlayMode 8개 통과**. 기존 마우스/키보드·상세보기·입력 잠금·Scene 로딩에 더해 AI 다중 제출, 중앙 공개, 중복 입력 차단, 자동 순서 전환과 AI 보상 처리를 확인했습니다.
- 40라운드 전원 규칙 기반 AI 시뮬레이션이 종료되며 수치 범위·코스트·행동 상한을 지킵니다. 이 검증에서 사람 자리도 테스트 에이전트로 제어하지만 실제 데모는 아래쪽 플레이어를 사람이 조작합니다.
- 추가 보존 검증: 덱 잔여 2장을 먼저 뽑고 재섞기로 나머지 3장 드로우, 사용 카드 재요청 거부, 라운드 정리 시 중복 버리기 방지. 40라운드 동안 매 효과/보상/라운드 전환 이후 모든 GUID의 중복과 이미 알려진 카드의 소실을 검사합니다.
- PlayMode에서는 중앙에 공개된 GUID가 이동 연출 중 손패, 효과 적용 후 버린 더미에 정확히 한 번 존재하는지와 사람의 사용 연출 후 GUID도 같은 모델 카드를 참조하는지 확인합니다.
- 1920×1080 실제 Canvas 렌더링에서 한글과 간소화된 UI 배치를 확인했습니다.
- 검증 산출물과 격리 Unity 프로젝트는 OS 임시 디렉터리에 생성합니다. 원본 프로젝트의 Library/Temp/Logs를 수동 수정하거나 Git에 추가하지 않습니다. 패키지 추가는 없습니다.

Unity에서 직접 확인하려면 **Window → General → Test Runner → EditMode / PlayMode → Run All**을 사용하세요. 명령줄 도구의 Unity 경로가 다르면 `verify_v2.ps1 -EditorData ...`, `verify_unity.ps1 -EditorPath ...`로 지정합니다.

## 1. 면죄부 수정

변환 코드 자체는 `SessionCardEffects.Execute`에 존재했지만, 데이터의 `EffectKey`가 `basic`이어서 변환 핸들러의 검증과 실행을 모두 건너뛰고 있었습니다.

- `CardCatalogData.cs`의 면죄부 키를 `Indulgence`로 수정했습니다.
- `Tools/import_card_design.py`도 함께 수정하고 재생성했습니다. `--check`로 생성 결과 일치를 확인했습니다.
- 기존 특수 핸들러를 그대로 재사용합니다. 비용 0, 헌금 +6, 교회 재산 +6, 신앙심/교리 정합성 각각 -10, 덱 위쪽의 효과 대상 신도 2장을 이단으로 변환합니다.
- 신실한 신도는 건너뜁니다. 변환 대상은 동일 객체와 GUID, 소유자, 덱 위치를 유지합니다. 사용한 면죄부만 손패에서 버린 더미로 이동합니다.
- 중복 사용과 카드 수 손실/중복, 자원 변화, 첫 두 대상만 변환되는 것을 검사했습니다.

기존 `requireFullFollowerTargets` 설정이 면죄부에도 정상 적용됩니다. 기본값 `true`이면 대상 신도 2장이 부족할 때 사용 전 전체 효과를 차단합니다. `false`이면 있는 대상만 변환합니다. 이는 기획상 확정 조건이 아니라 기존 공통 임시 정책입니다.

## 2. AI 변경

기존에는 후보 하나를 고른 뒤 해당 대상 검증이 실패해도 카드 GUID 전체를 제외했습니다. 따라서 다른 교단에 유효 대상이 있어도 해당 카드를 포기했습니다.

현재 순서:

1. 자신의 손패와 공개 상태를 바탕으로 모든 카드·대상 조합의 점수를 계산합니다.
2. 중개 코드 `AiTurn`이 모든 조합을 인간과 동일한 `GameSession.CanPlay`로 검증합니다.
3. 유효한 조합 중 설정된 최소 전략 점수를 넘는 후보를 선택합니다. 비슷한 점수끼리의 제한적 무작위 선택은 유지합니다.
4. 공개 애니메이션 후 기존 `TryPlay`로 다시 검증하여 한 번만 실행합니다.
5. 자원과 상태가 변한 뒤 다음 결정을 새로 계산합니다. 후보가 없거나 전략 점수가 낮으면 정상 종료합니다.

`RuleBasedAi.EvaluateActions`는 음수 점수도 반환해 평가 여부와 전략적 미선택을 구분할 수 있습니다. 성직자 양성, 설파, 신앙의 결속, 공의회, 추수꾼, 공개 비난, 축복, 털갈이 의식 모두 평가 및 실제 실행 회귀 검사를 추가했습니다. 기본 가중치를 강제로 올리거나 점수를 양수로 보정하지 않았습니다. 기본 전략에서 일부 카드를 계속 선택하지 않을 수 있습니다.

유효 대상 탐색 실패는 행동 횟수 상한을 소모하지 않습니다. 한 번의 결정에서 유한한 후보 목록만 검사합니다. `Attempts`는 반환한 카드 제출 횟수이며, 별도 `LegalityChecks`로 검증 횟수를 확인할 수 있습니다. 반환한 카드 GUID는 해당 행동 턴 동안 제외하므로, 공개 중 상태가 바뀌어 사용이 실패해도 같은 카드를 계속 재제출하지 않습니다. 게임의 카드 사용 횟수 규칙은 바꾸지 않았습니다.

AI 평가기에 상대 손패, 덱 카드 객체, 덱 순서 또는 실패 이유를 전달하지 않습니다. 중개 코드가 대상의 사용 가능 여부만 공통 엔진에 확인합니다.

임시 정책인 무신론자 부족/신도 부족/자기 교단 지정 허용 여부도 AI 관측값에 전달합니다. 기존의 AI 전용 고정 제한과 엔진 설정이 어긋나는 문제를 없앴습니다. 자기 교단 지정 허용 시 UI 대상 버튼에도 자신이 포함됩니다. AI 점수에서 자신에게 피해를 주는 효과를 상대 견제로 잘못 계산하지 않습니다.

## 3. 자동 진행 안정성

- 실험실은 별도 게임 상태를 사용하며, 그 안에서 AI가 자동 행동하지 않는 기존 동작을 유지합니다.
- 실험실 패널 닫기와 정규 게임 복귀는 다릅니다. 정규 게임을 계속하려면 **정규 게임 복귀**를 눌러야 합니다.
- 실험실에서 새 게임을 눌러도 저장된 정규 게임의 AI 인스턴스와 무작위 상태를 초기화하지 않도록 수정했습니다.
- AI 실행/애니메이션 도중 실험실 진입과 중복 조작은 기존 잠금으로 차단합니다.
- 사용 실패 시 재시도 무한 루프 없이 다음 후보 또는 턴 종료로 진행합니다.
- 코루틴 종료 시 기존 `finally`가 실행 상태를 해제합니다. 컴포넌트 비활성화 시 코루틴 정지/잠금 해제, 재활성화 후 정상 재개를 실제 PlayMode에서 검사합니다.

현재 등록 38종 중 효과 구현 표시 31종, 그중 신도/신실한 신도 2종은 정상적인 사용 불가 카드입니다. 나머지 29종은 자원·대상·조건을 만족하면 사용할 수 있습니다. 이번에 **면죄부의 누락된 효과를 복구**했으며 신규 효과 구현 카드는 없습니다.

## 5. 명시된 규칙과 임시 제한

| 항목 | 분류 및 현재 처리 |
|---|---|
| 신도/신실한 신도 | 정상 사용 불가. 드로우 허용, 신자 수 집계 및 신실한 신도 보호 유지 |
| 헌금 비용 | 원문 및 대상 신앙에 따른 공격적 선교 비용 1/2 적용 |
| 한 줌의 희망 | 원문: 헌금 정확히 0 |
| 낙원 | 원문: 신도 수 20 이상 |
| 야성의 포효 | 원문: 신앙심 70 이상 |
| 포고령 | 원문: 자기 손패/덱에서 제거. 신실한 신도 제외는 보호 규칙. 사용 중인 자기 자신 제외는 현재 처리 정책 |
| 다른 교단만 지정 | 원문에 자기 대상 허용 여부 없음. `allowSelfAsOpponentTarget=false`는 임시 정책이며 이번에 확정 규칙으로 변경하지 않음 |
| 무신론자 부족 시 전체 차단 | `rejectWhenAtheistsInsufficient=true`는 임시 정책. 포교/야성의 포효에 적용. 부분 처리 여부 미확정 |
| 신도 수 부족 시 전체 차단 | `requireFullFollowerTargets=true`는 임시 정책. 면죄부/털갈이 의식/신앙의 결속/추수꾼/공개 비난/공격적 선교/빈민 구휼/축복 등에 적용 |
| 교단 카드 소속 | 정규 보상은 자기 교단 카드만 제공. 강제 지급 카드의 소속을 추가 사용 제한으로 검증하지 않는 기존 동작 유지. 획득 제한과 사용 제한은 별개 |
| 행동 횟수 | 정규 임시 설정 `maxCardsPerActionTurn=0` 유지. AI 안전 상한은 게임 규칙과 별개 |

신실한 신도의 자발적 증여 허용 여부, 사용 카드가 별도 영역에 머무는 기간, 정확한 승리 점수 계산도 여전히 확정하지 않았습니다. 현재 사용 카드는 즉시 버린 더미로 이동하고 중앙 공개 카드는 동일 GUID의 표시 참조만 보관합니다.

1. Unity 6000.6.9f1로 프로젝트를 엽니다. 메뉴 **Pilgrimage → v2 데모 열기** 또는 `Assets/Scenes/PilgrimageDemo.unity`를 열고 Play를 누릅니다. `SampleScene`은 기존 v1 테스트 장면입니다.
2. **카드 실험**에서 면죄부를 검색해 손패에 추가합니다. 기본 실험 세션에는 덱의 대상 신도 2장과 헌금 20이 준비되어 있습니다. 기본 5장 교체 기능으로 면죄부를 포함시켜도 됩니다.
3. 실험 패널의 **더미 / GUID 확인**에서 대상 신도 GUID를 기록합니다. 패널을 닫고 면죄부를 더블클릭하거나 선택 후 Enter를 누릅니다. 헌금 +6, 신앙/교리 -10, 신도 -2를 확인합니다. 내 교단 상세에서 교회 재산 +6과 덱/손패/버린 더미 수를 확인합니다. 다시 실험실의 더미/GUID 화면을 열면 같은 GUID의 신도 2장이 이단으로 바뀌어야 합니다. 같은 카드 반복 입력이 중복 적용되지 않아야 합니다.
4. 실험 세션에서 면죄부를 다시 추가하면 대상 신도가 부족할 수 있습니다. 기본 정책에서는 거절되는 것이 정상입니다. 실험실의 **편집할 교단 변경**으로 내 교단을 고르고 **이 교단 덱에 신도 추가**를 두 번 누르면 다시 시험할 수 있습니다.
5. **정규 게임 복귀** 후 **행동 종료**를 누릅니다. 상대 카드가 한 장씩 중앙 공개되고, 세 교단이 종료하면 정상 순서대로 진행하는지 확인합니다. 2라운드부터 선플레이어가 바뀌므로 내 차례가 올 때까지 AI가 더 진행할 수 있습니다.
6. 후보가 없는 상황은 실험실의 신도 5장 구성으로 사용 불가를 확인하고, 자동 테스트의 `AiChecksOtherTargetsAndEndsNormallyWithOnlyPassiveCardsLeft`로 AI 종료 경로를 재검증합니다. 점수가 불리해서 선택하지 않는 카드와 엔진에서 사용 불가인 카드를 구분해야 합니다.
7. **Window → General → Test Runner**의 EditMode/PlayMode에서 `Pilgrimage.Tests`를 실행할 수 있습니다.

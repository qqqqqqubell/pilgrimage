# Pilgrimage 프로토타입 v2

> 이 문서는 이전 26종 기획의 구현 기록입니다. 현재 38종 카드·AI 자동 플레이·라운드 규칙은 [2026-11-14 개선 안내](AiUpdate_2026-11-14.ko.md)를 따릅니다.

기준: `Docs/Pilgrimage_Game_Design_Latest.md`, Unity **6000.6.9f1**.

![1920×1080 데모 렌더링](Images/PilgrimageDemo.png)

## 데모 실행 — 수동 UI 제작 없음

1. Unity에서 컴파일/에셋 가져오기가 끝날 때까지 기다립니다.
2. 상단 **Pilgrimage → v2 데모 열기**를 선택합니다. 또는 Project 창의 `Assets/Scenes/PilgrimageDemo.unity`를 더블클릭합니다.
3. **▶ Play**를 누르고 **Game** 탭을 선택합니다. 1920×1080 또는 16:9 비율을 권장합니다.
4. 실행 시 Canvas, TextMeshPro 텍스트, EventSystem, 입력 액션, 카드/상태 패널이 자동 생성됩니다. Scene 편집 상태에는 데모 루트만 보이는 것이 정상입니다.

기존 `SampleScene`과 v1 IMGUI 화면은 보존했습니다. 빌드 장면 목록도 변경하지 않았습니다. 실행 파일로 데모를 빌드하려면 Build Profiles의 Scene List에 **PilgrimageDemo**를 직접 추가하세요.

### 조작

| 입력/버튼 | 동작 |
|---|---|
| 카드 위로 마우스 이동 | 같은 선택 상태로 카드 돌출, 형광 테두리, 앞쪽 표시 |
| 카드에서 마우스 이동 | 마우스로 선택했을 때 기본 위치 복귀 |
| 우클릭 | 선택 카드 상세 정보 열기. 열린 상태에서 우클릭하면 닫기 |
| 더블 좌클릭 | 카드 사용 시도. 단일 좌클릭은 선택만 수행 |
| ← / → | 내 손패의 이전/다음 카드 선택, 양 끝에서는 순환 |
| Space | 선택 카드 상세 정보 열기/닫기 |
| Enter | 선택 카드 사용. 상세보기가 열려 있을 때는 사용하지 않음 |
| ESC | 상세보기 닫기 |
| 내 행동 종료 (임시) | 내 순서 종료. 손패 정리는 임시 설정을 따름 |
| 테스트 교단 행동 1회 + 종료 | 현재 상대 교단이 사용할 수 있는 첫 카드 1장을 시도하고 순서를 넘김. 전략 AI가 아님 |
| 대상 변경 | 대상 지정 카드의 상대 교단을 상단→좌측→우측 순서로 선택 |
| 내 추가 상태 / 상태 | 신앙심·교리 정합성·교회 재산·더미 개수 확인. 상대 카드 이름은 공개하지 않음 |
| 카드 목록 26종 | 공용 카드 사전. 개인이 보유한 비공개 카드 목록과 무관 |
| 초기화 | 같은 설정으로 새 게임 생성 |

내 카드가 아닌 순서에는 내 카드를 사용할 수 없습니다. 비용·조건 부족 시 중앙에 사유가 표시되고 자원·더미는 바뀌지 않습니다. 성공한 카드는 상태에 한 번 반영한 뒤 약 0.25초 동안 위로 사라지고, 손패가 다시 정렬됩니다. 애니메이션 도중 사용·선택·턴 전환·초기화 입력은 차단합니다.

상대 패널에는 손패 수만큼 익명 뒷면을 생성합니다. 뒷면 오브젝트에는 `CardInstance`, 이름, 효과, 개별 ID를 연결하지 않습니다. 내 카드의 상세 정보 패널은 상대 비공개 뒷면과 별도 UI입니다.

### 전체 카드 실험

**카드 목록 26종 → 실험: 26종 손패 추가 + 자원 설정**을 누르면, 내 손패에 26종이 각각 1장 추가되고 헌금 50·신앙심/교리 정합성 80·교회 재산 20이 됩니다. 이 버튼은 정규 획득 규칙을 우회하는 디버그 도구입니다. 다른 교단의 카드도 효과 검증을 위해 지급합니다. 사용 가능 여부는 실제 세션 로직이 다시 검증합니다.

손패가 많아지면 겹침이 커지므로 방향키로 선택하면 편합니다. 기본 5장 외에 1·7·31장도 같은 부채꼴 배치 계산을 사용합니다. 드래그 사용은 구현하지 않았습니다.

## 확정 규칙과 구현 상태

- 4개 교단, 총 40라운드. 신앙심·교리 정합성은 v2에서 항상 0~100.
- 각 플레이어 초기 신앙심/교리 정합성 50, 공용 무신론자 100.
- 초기 덱: 신도 5, 포교 4, 헌금 요구 3, 정기 예배 3 — 총 15장.
- 라운드 시작마다 각 교단에 헌금 5와 드로우 5장. 첫 라운드도 지급합니다.
- 덱 소진 시 자신의 버린 더미를 섞어 드로우를 계속합니다.
- 선플레이어는 0→1→2→3 순환. 한 라운드에 네 교단의 순서를 모두 처리한 뒤 라운드가 증가합니다.
- 4·12·20·28·36 종료 시 일반 카드 8종 중 1장 선택(신도·이단 제외).
- 8·16·24·32·40 종료 시 자기 교단 카드 4종 중 1장 선택. 신실한 신도와 미구현 카드도 획득 가능하며, 획득과 사용 가능 여부를 구분합니다.
- 40라운드 보상 선택이 모두 끝나면 종료합니다. 임의의 승리 점수나 동점 규칙은 추가하지 않았습니다.
- 기존 포교·헌금 요구·정기 예배는 같은 카드 데이터와 공통 수치 효과 처리기를 사용합니다.
- 각 실물 카드의 GUID는 드로우·버리기·재섞기·강탈·변환 중에도 보존합니다. 새 카드 생성만 새 GUID를 받습니다. 제거된 카드도 별도 Removed 영역에서 추적하지만 보유/신도 수에는 포함하지 않습니다.
- 신실한 신도는 신도 수에 포함되며, 모든 카드 효과 기반 변환·제거·강탈 진입점에서 보호합니다. 일반 드로우와 손패 정리에는 정상 참여합니다. 코스트는 **원문 미명시(-1 센티널)**이고 사용 불가입니다. 0코스트로 간주하지 않습니다.
- 이자는 교회 재산의 10%를 버림 처리하며, 예전의 턴당 1회 제한을 적용하지 않습니다.
- 신앙의 결속은 등록하지 않았습니다.

### 카드별 효과 연결

| 분류 | 효과 연결 완료 | 데이터만 등록, 사용 차단 |
|---|---|---|
| 일반 10종 | 신도(사용 불가), 포교, 헌금 요구, 정기 예배, 성직자 양성, 이단(사용/종료 트리거), 공개 비난, 공의회, 추수꾼, 공격적 선교 | 없음 |
| 청빈의 사도단 | 빈민 구휼, 구세군 모금, 자선냄비 | 누추한 성전 |
| 순금의 형제단 | 십일조, 이자, 면죄부 | 성전 리모델링 |
| 절대 교율 교단 | 이단 심문관, 성서무오론, 고해성사 | 교황 |
| 숲의 털가죽 교단 | 신실한 신도(상시 보호), 털갈이 의식, 깊은 숲의 성역, 야성의 포효 | 없음 |

26종 중 23종의 동작/상시 특성을 연결했고, 그중 신도·신실한 신도는 사용하는 카드가 아닙니다. 3종의 지속 효과는 턴 기산·수입 범위·중첩 방식이 불명확하여 미구현으로 표시합니다. 성전 리모델링의 데이터에는 **교회 재산 -4**가 등록되어 있으나 지속 효과를 포함한 카드 전체 실행은 차단합니다. 일부 효과만 조용히 적용하지 않습니다.

`ICardEffectHandler`와 `CardEffectContext`는 대상 검증, 카드 이동/변환, 교단 상태 및 지속 보호 효과 확장을 위한 경계입니다. 미등록 핸들러는 기본 효과로 대체 실행하지 않습니다. 지속 효과 데이터 모델은 있으나 위 3종의 최종 실행 규칙은 구현하지 않았습니다.

## 임시 가정 — 최종 규칙 아님

`DemoRuleAssumptions`에 확정 수치와 별도로 저장합니다. Inspector에서 바꾸려면 **Create → Pilgrimage → v2 데모 설정**으로 에셋을 만들고 Demo Scene 루트의 **Settings**에 연결하세요. 변경 후 초기화하거나 Play를 다시 시작해야 적용됩니다.

| 필드/항목 | 기본 동작 및 미확정 부분 |
|---|---|
| Starting Offering | 라운드 지급 전 0. 첫 라운드 지급 후 5 |
| Starting Church Property | 0. 교회 재산의 최종 하한은 미정 |
| Shuffle Initial Deck / Random Seed | 시작 덱을 섞음, 시드 20261114로 재현 |
| Discard Remaining Hand At Action End | 켜짐. 이단의 종료 효과를 먼저 처리하고 남은 손패를 버림 |
| Accumulate Offering Between Rounds | 켜짐. 사용하지 않은 헌금은 다음 라운드로 누적 |
| Max Cards Per Action Turn | 0(무제한). 교단별 명시적 행동 종료까지 사용. 행동 횟수 최종 규칙 아님 |
| Reward Destination | Discard. 라운드 종료 후 즉시 각 교단이 선플레이어 순서로 수동 선택. 40라운드 보상도 처리 |
| Reject When Atheists Insufficient | 켜짐. 포교/야성의 포효의 무신론자가 부족하면 전체 사용 거부. 꺼짐이면 감소 후 공용 수치 하한 0 |
| Require Full Follower Targets | 켜짐. 필요한 수의 조작 가능한 신도가 부족하면 전체 사용 거부. 꺼짐이면 가능한 수만 처리 |
| Allow Self As Opponent Target | 꺼짐. 대상 지정 카드는 다른 교단만 선택. UI는 다른 세 교단만 순환 |
| 카드 제출 | 선플레이어부터 교단별 순차 즉시 실행. 동시 제출/해결 큐/반응창은 미구현 |
| 특정하지 않은 덱 위치 | 일반 추가는 덱 끝. 공개 비난·추수꾼·공격적 선교는 위쪽부터 조작 가능한 신도 선택. 빈민 구휼은 아래쪽부터 선택 |
| 턴과 라운드 | 현재 이단의 ‘턴 종료’는 소유 교단의 행동 종료로 해석. 지속 효과의 2·3턴 기산과 중첩은 확정 필요 |
| 깊은 숲의 성역 | 손패+덱의 신실한 신도 수를 합쳐 4장 단위로 버림 계산. 나머지/부분 장수 계산은 기획 확인 필요 |
| 최종 승리 | 원문 ‘신자 수’와 ‘가장 많은 카드’가 혼재. 신도 수와 총 보유 카드 수를 각각 표시하고 승자 선정·동점 처리는 보류 |

손패 상한, 교단 카드의 강탈 후 사용 자격, 지속 효과가 라운드 헌금 외 카드 헌금에도 적용되는지, 피해 배수와 무효화의 우선순위도 기획 확인이 필요합니다.

## 폰트·아트·해상도

- CanvasScaler는 기준 1920×1080, Expand 모드로 화면 비율이 달라져도 테이블과 패널 전체가 들어가도록 설정합니다.
- 프레임은 카드 종류별 색상, 일러스트는 임시 기호입니다. DemoSettings의 종류별 Card Frame, Card Illustration, Card Back에 Sprite를 넣으면 교체됩니다.
- 설치된 uGUI가 제공하는 공식 **TMP Essential Resources**만 가져왔습니다. 새 패키지를 설치하지 않았습니다. 포함된 폰트/셰이더의 라이선스는 `Assets/TextMesh Pro` 아래 원본 고지에 보존됩니다.
- 기본 한글 폰트는 OS의 맑은 고딕 등으로 동적 TMP 폰트를 생성합니다. 한글 글리프도 검사합니다. Windows의 맑은 고딕 파일은 시스템에 존재함을 확인했습니다.
- 다른 OS/배포 환경에서는 한글 TMP Font Asset을 DemoSettings의 Korean Font에 연결하세요. 상용 OS 폰트를 프로젝트에 무단 복사하지 않았습니다. 렌더링 최종 품질은 Game 창에서 확인해야 합니다.

## 테스트

Unity의 **Window → General → Test Runner**에서:

1. **EditMode → Run All**: 기존 13개 + 신규 14개 = 27개. 26종 데이터, 초기 덱, 40라운드와 모든 보상 일정, 수치 범위, 비용 실패, 신실한 신도, 강탈·변환·제거의 GUID, 이자 반복 사용, 재섞기, 부채꼴 계산을 검증합니다.
2. **PlayMode → Run All**: 실제 Canvas/TMP 생성, 상대 뒷면 익명성, 키보드/포인터 선택 공유, 상세보기, 더블클릭, 효과 적용, 애니메이션 잠금 및 손패 재생성을 검증합니다.

최종 검증 결과:

- 기존 13개 + 신규 14개 로직 테스트 **27/27 통과**. Mono에서 같은 NUnit 테스트 본문을 실행했습니다.
- Unity 6000.6.9f1의 실제 PlayMode 테스트 **5/5 통과**. 위 동작 외에 제공된 Demo Scene을 직접 로드해 수동 참조 없이 시작하는 것도 검증했습니다.
- 설치된 Unity 엔진·uGUI·TMP·Input System 라이브러리를 참조하여 런타임/UI/에디터/EditMode·PlayMode 테스트 어셈블리 컴파일 성공.
- OS 임시 디렉터리에 만든 격리 Unity 프로젝트에서 검증했고, 원본 프로젝트의 자동 생성 폴더는 수동으로 수정하지 않았습니다. 테스트용 격리 프로젝트에는 기존 패키지의 로컬 경로만 연결했습니다.
- 동적 TMP 한글 글리프 검사 통과. 제공 Demo Scene을 1920×1080 RenderTexture로 렌더링해 위 이미지의 한글·배치·카드 앞면과 상대 뒷면을 직접 확인했습니다. 물리 마우스 조작은 자동 포인터/키보드 이벤트 테스트로 검증했습니다.
- 신규 스크립트/테스트 `.meta` 누락 0, 전체 Assets 에셋 GUID 중복 0. 기존 Scene·설정·테스트·v1 UI·Packages·ProjectSettings에 변경 없음.

명령줄 로직 검증: PowerShell에서 `./Tools/verify_v2.ps1`. Unity 경로가 다르면 `-EditorData '설치경로/Editor/Data'`를 지정합니다. 기존 Unity 라이브러리로 런타임/UI/에디터/테스트를 컴파일하고, 같은 NUnit 로직 테스트를 Mono에서 실행합니다. 컴파일 결과는 OS 임시 디렉터리에만 저장합니다. 프로젝트의 Library/Temp/Logs는 읽기만 하며 Git에 추가하지 않습니다.

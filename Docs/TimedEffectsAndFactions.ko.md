# 지속 효과 7종 완성 및 교단 선택 — 2026-11-15

기준은 `Docs/Pilgrimage_Game_Design_2026-11-14.md`입니다. `Docs/CardAuditReport.ko.md`는 현재 프로젝트에 없어 현재 소스와 [이전 수정 기록](CardSystemFixReport.ko.md)을 직접 대조했습니다. 기존 카드 효과 핸들러, 카드/손패 UI, 카드 실험실과 Scene을 재사용했습니다.

## 구현 카드

| 카드 | 비용 | 실제 효과 | 사용 조건/대상 |
|---|---:|---|---|
| 고행 | 3 | 5회 후 헌금 +6, 신앙심/교리 정합성 각각 +10 | 예약 효과. 즉시 보너스를 지급하지 않음 |
| 고독한 성찰 | 1 | 즉시 신앙심/교리 +10, 다음 라운드 수입 절반·소수점 버림 | 기본 수입 5라면 다음 수입은 2 |
| 대상단 투자 | 1 | 2회 후 무작위 헌금 0~5 획득 | 양 끝값을 포함. 시드로 재현 가능 |
| 마녀사냥 | 0 | 신도 1장을 이단으로 변환, 헌금 +3 | 기본 임시 대상은 자기 덱 맨 위의 조작 가능한 신도. 없으면 지급 전 거절 |
| 누추한 성전 | 2 | 즉시 신앙심/교리 +15, 다음 2회 라운드 수입 -3 | 기본 수입은 5→2→2→5로 복귀 |
| 성전 리모델링 | 3 | 즉시 교회 재산 -4, 다음 2회 수입 ×2, 활성 기간 동안 카드로 인한 신앙심/교리 감소량 ×2 | 기본 정책은 재산 부족을 추가 사용 조건으로 삼지 않으며 음수 재산 허용 |
| 대주교 | 4 | 활성 기간 동안 카드로 인한 신앙심/교리 감소 무시, 3회 정산 후 종료 | 증가 효과는 허용. 리모델링의 감소 배율보다 보호 우선 |

모든 카드가 공통 `CanPlay`/비용 지불/핸들러/버린 더미 경로로 실행됩니다. 대상이 없거나 비용이 부족한 실패는 자원이나 예약/지속 효과를 만들지 않습니다. 원문 이름·설명·조건·Flavor Text는 생성 데이터에 유지합니다. 미구현 7종을 `Implemented`로 갱신하고, 생성기도 함께 수정했습니다. 현재 38종 모두 효과 또는 상시 특성이 연결되어 있으며, **사용 가능한 행동 카드 36종 + 정상 사용 불가인 신도류 2종**입니다.

## 공통 지속·예약 처리와 임시 정책

`TimedCardEffects.cs`에 공통 등록·수입 계산·감소 보정·예약 지급·만료 처리를 추가했습니다. `TimedCardEffect`는 원본 카드 ID/GUID, 종류, 남은 정산 횟수를 저장합니다. 원본 카드를 복제하거나 별도 물리 더미에 넣지 않습니다.

다음은 확정 기획이 아닌 현재 기본 처리입니다.

| 모호한 항목 | 기본 정책 | 변경 방법 |
|---|---|---|
| 턴의 기산 | ‘다음 라운드 시작 시 해당 교단의 수입 정산’을 1회로 셈. 고행은 사용 R의 R+5, 투자는 R+2에서 지급 | 라운드 수입 정산 경계에서 한 번씩 처리하는 별도 공통 정책 |
| 지속 기간 | 사용 즉시 활성화. 다음 N번째 수입까지 적용한 뒤 해당 정산 직후 제거. 예: R1 리모델링은 R2·R3 수입을 바꾸고 R3 행동 전 만료 | `TimedEffectPolicy.durationIncludesActivationRound`; true이면 지속형의 다음 정산 잔여 횟수에서 1을 빼되 최소 1. 예약 지연 시간은 변경하지 않음 |
| 같은 지속 카드 중첩 | 각 사용을 독립 등록. 수입 증감은 합산, 배율은 곱함 | `stacking=RefreshSameCard`이면 같은 카드 종류·효과 종류를 새 기간으로 갱신. 다른 카드 종류는 공존 |
| 예약 카드 중첩 | 고행/투자는 각 사용이 별도로 예약·지급됨 | 지속형 중첩 옵션과 분리 |
| 수입 범위 | 라운드 기본 지급 5에만 적용. 카드의 즉시 헌금 획득, 고행 보상, 투자 보상에는 적용하지 않음 | `BeginRound`의 별도 수입 정책. 범위가 확정되면 이 경로를 변경 |
| 수입 연산 순서 | `(기본 수입 + 증감 합계) × 배율 곱`, 최종 소수점 버림, 수입 최소 0 | `incomeOrder=MultiplyThenAdd`이면 배율 후 증감. 기존 보유 헌금은 감소시키지 않음 |
| 보호·감소 배율 | 대주교 보호 → 감소 배율 → 0~100 제한. 회복은 배율·보호 대상 아님 | 공통 카드 능력치 처리 경로 |
| 마녀사냥 대상 | 자기 덱 위에서 첫 조작 가능한 신도. 신실한 신도 제외, 대상 없으면 차단 | `witchHuntSource=OwnHandFirst`이면 자기 손패의 첫 조작 가능한 신도. 소유/더미/선택 방식은 기획 확정 필요 |
| 재산 부족 | 리모델링이 재산을 4 감소시키며 음수 허용. 원문에 없는 재산 조건을 기본 제한으로 추가하지 않음 | `remodelingRequiresProperty=true`이면 재산 4 이상 요구 |
| 무작위 분포 | 투자는 0·1·2·3·4·5 균등 추출. 셔플과 별도 시드 난수열 사용 | 분포는 원문에 없어 임시 정책. `DemoRuleAssumptions.randomSeed`로 재현 |
| 예약 원본 이동/제거 | 발동된 효과는 원본 카드가 재순환/제거되어도 유지. 매 예약은 한 번만 지급 | 원본 GUID를 추적하되 원본 위치로 예약을 취소하지 않는 정책 |
| 40라운드 종료 후 | 추가 라운드나 예약 보상 정산을 만들지 않음. 아직 도래하지 않은 예약은 기록만 남고 미지급 | 게임 종료 이후 지급 여부 기획 확인 필요 |

예를 들어 같은 턴에 누추한 성전과 리모델링을 사용하면 기본 순서는 `(5-3)×2=4`입니다. 고독한 성찰 두 장은 기본 독립 중첩에서 `floor(5×0.5×0.5)=1`입니다. 중첩 옵션은 최종 규칙을 의미하지 않습니다.

정책은 `DemoRuleAssumptions.timedEffects`에 묶었고 게임 생성 시 복사합니다. 에디터에서 설정 자산을 수정해도 이미 생성된 세션의 정책이 바뀌지 않습니다. 기존 자기 대상 지정/공용 무신론자 부족/신도 부족 관련 임시 설정은 유지합니다. 신실한 신도는 신자 수에 포함되며 드로우 가능하지만 사용·변환·제거·강탈할 수 없습니다.

## 교단 선택 구조

- 시작 시 uGUI 교단 선택 화면만 표시하고 **GameSession은 아직 생성하지 않습니다.** 따라서 라운드, 초기 수입·드로우, AI가 먼저 진행되지 않습니다.
- 선택 버튼을 누르면 `FactionSetup.Seats`가 선택 교단을 인덱스 0에 배치하고 나머지를 기존 교단 순서대로 1~3에 중복 없이 배치합니다.
- 인간은 항상 인덱스 0입니다. AI는 1~3입니다. 선플레이어는 교단과 무관하게 기존 좌석 순환을 유지합니다.
- 보상은 `Players[RewardPlayerIndex].Faction`으로 필터링합니다. 순금 선택 시 8라운드에 면죄부·십일조·이자·리모델링이 보입니다.
- AI 프로필은 관측한 실제 `PlayerState.Faction`으로 선택하므로 좌석을 바꿔도 기존 교단별 가중치를 적용합니다.
- 추가적인 ‘교단 전용 카드의 사용 자격’ 차단은 만들지 않았습니다. 정규 획득은 자기 교단 보상, 실험실에서는 모든 교단 카드 사용이 가능합니다.
- 패널 이름과 대상 지정은 실제 좌석의 플레이어 정보를 읽습니다. 실험실은 선택한 인간 교단을 유지하는 별도 게임을 생성하며, 정규 게임의 자원/진행/지속 효과를 변경하지 않습니다.
- 정규 **새 게임**은 교단 선택으로 돌아갑니다. 실험실의 새 게임은 해당 실험 세션만 초기화합니다.
- 기존 승리 점수/동점 처리는 아직 구현되지 않았으며 40라운드 종료만 제공합니다. 교단 선택을 이유로 새로운 점수 규칙을 만들지 않았습니다.

## AI 연결

7종 모두 실제 구현 상태와 공통 비용·대상 검증을 거쳐 평가합니다. 마녀사냥은 자신의 설정된 더미에 대상이 있는지, 리모델링은 선택한 재산 정책을 만족하는지 확인합니다.

예약 보상은 남은 라운드가 충분할 때만 기대 가치를 평가합니다. `AiSettings.delayedRewardDiscount`로 미래 가치 할인율을 조정합니다. 지속 수입 변화·보호·재산 감소의 위험은 기존 교단 가중치로 평가합니다. 중첩과 미래의 모든 카드를 정확하게 예측하는 최적 전략은 아니며, 현재 비용·효과·남은 기간을 사용하는 규칙 기반 추정입니다. 음수 점수를 강제로 양수로 만들지 않았습니다.

선택 후 공개 중 상황이 바뀌면 `TryPlay`가 재검증합니다. 실패한 카드는 같은 행동 턴에 반복 제출하지 않으며 다음 후보가 없으면 정상 종료합니다. 기존 AI 안전 상한과 비공개 카드 정보 분리를 유지합니다.

## Unity에서 직접 확인

1. Play를 중지하고 컴파일을 기다린 뒤 **Pilgrimage → v2 데모 열기**로 기존 `PilgrimageDemo` Scene을 엽니다. `SampleScene`은 기존 v1 테스트용 장면입니다.
2. Play를 누르면 교단 선택 화면이 나옵니다. 선택하기 전에는 게임 상태가 생성되지 않습니다. 원하는 교단의 **선택** 버튼을 누릅니다.
3. 하단이 선택 교단인지, 나머지 세 패널에 다른 교단이 한 번씩 표시되는지 확인합니다. 초기 헌금 5, 신앙/교리 50, 신도 5, 손패 5입니다.
4. **카드 실험**에서 새 7종 중 원하는 카드를 검색해 **손패 +1**로 추가하고 **필드로 닫기**를 누릅니다. 더블클릭/Enter로 사용합니다. 실험 세션은 헌금 20이며 대상 신도 2장이 덱에 준비됩니다.
5. **내 추가 상태**에서 다음 수입과 남은 정산 횟수를 확인합니다. 예: 누추한 성전은 즉시 신앙/교리 65, 다음 수입 2입니다.
6. 실험 패널의 **다음 내 차례로**를 누를 때마다 다음 정산을 확인할 수 있습니다. 누추한 성전은 2회, 대주교는 3회 후 사라집니다. 고행은 5회 후, 투자는 2회 후 지급됩니다. 실험실에서 AI가 자동 진행하지 않는 것은 의도된 동작입니다.
7. 면죄부는 덱의 신도 2장이 필요합니다. 부족하면 실험실에서 편집 교단을 내 교단으로 바꾸고 **이 교단 덱에 신도 추가**로 대상을 마련합니다. 더미/GUID 화면으로 같은 카드가 이단으로 변했는지 확인합니다.
8. **정규 게임 복귀** 후 **행동 종료**를 누르면 AI가 중앙에 카드를 공개하고 진행합니다. 새 게임은 메뉴에서 다시 교단을 선택할 수 있습니다.
9. 순금을 선택한 정규 게임에서 8라운드 보상에 면죄부가 나타납니다. 획득은 기존 임시 기본 위치인 **버린 더미**입니다. 즉시 손패에 생기는 것이 아니라 이후 덱 재순환과 드로우로 손패에 들어옵니다.
10. 자동 검사는 **Window → General → Test Runner**의 EditMode/PlayMode에서 `Pilgrimage.Tests`를 실행합니다. 40라운드 UI 검사는 시간이 걸리며 유한 시간 제한 안에서 실제 AI를 진행합니다.

정책 변경이 필요한 경우 **Assets → Create → Pilgrimage → v2 데모 설정**으로 DemoSettings 자산을 만들고 Scene의 DemoController의 Settings 필드에 연결합니다. **Assumptions → Timed Effects**에서 위 정책을 선택한 다음 새 게임을 시작합니다. 직접 UI를 제작할 필요는 없습니다.

PowerShell 검증 명령:

```powershell
& Tools/verify_v2.ps1
& Tools/verify_unity.ps1 -Platform EditMode
& Tools/verify_unity.ps1 -Render
# Python 경로가 설정되어 있는 환경:
python Tools/import_card_design.py --check
```

모든 검증용 복사본·로그·XML·화면은 OS 임시 폴더에 생성합니다. 원본 프로젝트의 Library/Temp/Logs는 검증용으로 수정하거나 Git에 추가하지 않습니다.

## 변경 파일

새 런타임 C# 및 동일 이름 `.meta`:

- `Assets/Scripts/Pilgrimage/Game/TimedCardEffects.cs`: 지속·예약 효과, 기간/중첩/수입/대상 정책.
- `Assets/Scripts/Pilgrimage/Game/FactionSetup.cs`: 교단 이름·특징·좌석 배정.
- `Assets/Scripts/Pilgrimage/UI/V2/FactionSelectionUI.cs`: 기존 DemoController의 partial 확장, 시작/새 게임 선택 화면.

기존 런타임 C# 수정:

- `Core/PlayerState.cs`: 지속·예약 효과 목록.
- `Core/CardEffectResolver.cs`: 감소 보호/배율 연결, 자원·수치 범위 유지.
- `Game/GameSession.cs`: 선택 교단 초기화, 라운드 정산/만료, 별도 효과 난수열.
- `Game/SessionCardEffects.cs`: 7종 검증/실행, 기존 핸들러 재사용.
- `Game/GameDebugTools.cs`: 인간 교단을 보존한 별도 실험 세션.
- `Cards/CardCatalogData.cs`: 완성한 효과의 데이터/핸들러/Implemented 갱신.
- `AI/AiStrategy.cs`: 신규 효과와 실제 교단/정책을 반영한 평가.
- `UI/V2/DemoController.cs`: 선택 후 시작, 새 게임, 추가 상태 표시.
- `UI/V2/CardLabUI.cs`: 선택 전 진입 차단 및 선택 교단 보존.

검사 및 도구:

- 새 `Assets/Tests/EditMode/ExpansionTests.cs`, `Assets/Tests/PlayMode/ExpansionInteractionTests.cs` 및 `.meta`.
- 기존 `GameSessionTests.cs`, `AiStrategyTests.cs`, `DemoInteractionTests.cs`: 새 구현/선택 흐름에 맞춘 회귀 기대값.
- `Tools/import_card_design.py`: 재생성 시 구현 상태와 즉시 효과 보존.
- `Tools/verify_v2.ps1`: 신규 모델 검사 포함.
- `Tools/verify_unity.ps1`: 교단 선택 화면 렌더링 검증 추가.
- 본 문서, `Docs/CardLab.ko.md`, 이전 수정 보고서의 후속 안내.

Scene, Packages, ProjectSettings는 변경하지 않습니다. Commit/Push는 수행하지 않습니다.
